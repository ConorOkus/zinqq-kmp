## Residual Review Findings

- **P1** `androidApp/src/main/kotlin/zinqq/spike/android/WalletViewModel.kt:102` — **Android back-press exit never stops the node; relaunch builds a second live node** (adversarial, 75). `onCleared()` detaches the lifecycle observer and `viewModelScope` is already cancelled, so the node's runtime keeps running headless in the cached process; relaunch creates a second Wallet over the same `filesDir/wallet` — two ChannelManagers on one node identity, last-writer-wins persistence. Fix: stop the node in `onCleared()` on a scope that survives teardown, or hold the Wallet in a process-level singleton.
- **P1** `rust/src/liquidity/mod.rs` (`on_open_channel_request`, formerly `liquidity.rs:607`) — **KTD-9 0-conf acceptance/rejection gate has zero test coverage** (testing, 75). The fund-safety trust gate the plan names "the likeliest silent-failure cluster" has neither its accept nor its reject branch exercised. Fix: unit-test both branches via the existing `build_source()` harness, extracting the accept-vs-reject decision into a pure function if ChannelManager side-effects resist observation.
- **P2** `iosApp/iosApp/WalletModel.swift:99` — **iOS cancel-and-restart event loop violates the queue's single-consumer contract** (adversarial, 75). On a quick background/foreground flip, an old loop parked on `nextEvent` can already hold the front event when `cancel()` lands; old and new loops both observe it and the second ack pops the next event unhandled (a `PaymentReceived` can vanish). Fix: await the old loop task's completion after cancel before spawning the new loop.
- **P2** `rust/src/node.rs:145` — **ClaimTracker rebuilt on every node start makes an outstanding JIT invoice unclaimable after a background flip** (adversarial, 75). The skim allowance is registered in an in-memory tracker that a foreground-only lifecycle resets on every background flip, so a payment against a pre-flip invoice fails back on every retry after the LSP already opened the channel. Fix: lift the tracker to Wallet scope or persist expected fees by payment hash, expiring with the invoice.
- **P2** `rust/src/node.rs:546` — **node::handle_ldk_event switchboard, including SpendableOutputs persist-or-replay, is untested** (testing, 75). The funds-safety branch that prevents stranded money on channel close has no direct test. Fix: call `handle_ldk_event` with fabricated events using the CapturingSink pattern from `payment.rs`; assert persist-failure returns `Err(ReplayEvent)`.
- **P3** `androidApp/src/test/kotlin/zinqq/spike/android/WalletViewModelTest.kt:14` — **WalletViewModel.reduce(): 4 of 12 event branches untested** (testing, 75, gated_auto). `PaymentSuccessful`, `ChannelPending`, `ChannelReady`, and `Lsps2Failed` (which clears the displayed invoice) have no test case. Fix: four small cases mirroring the existing style.
